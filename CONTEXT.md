# Opzava ubiquitous language (canonical glossary)

Use these terms EXACTLY. If a doc, issue, or conversation uses a term differently, this file wins;
if a new term crystallises, add it here in the same slice. Definitions only — design detail lives in
`ARCHITECTURE.md`, current PRDs/ADRs, and their current foundation decision ledgers.

WF-231-added GitHub vocabulary is reserved target terminology but does not activate the prepared
#231 mirror contract before parent-map closure and explicit migration-manifest designation.

The WF-234-added `Document Owner`, `Document Finalization Authority Envelope`, and
`Reliance Invalidation Interruption` terms are likewise reserved target vocabulary and do not
activate the prepared Governed Docs contract before parent-map closure and explicit
migration-manifest designation.

| **Admin Overview**                           | The read-only, cross-context landing composition of the Admin Control Center.                                                                                                                                                                                                                                                                                                                                                                                                         | Dev Board Summary; a mutation authority; a competing OpenClaw Overview route.                                                                                                                                      |
| **User dashboard**                           | The future user-facing product surface family and permanent home of the deferred CRM rebuild. CRM currently has no surface; it returns here, not in the Admin Control Center (GitHub issue #200, 2026-07-15).                                                                                                                                                                                                                                                                         | Admin Control Center.                                                                                                                                                                                              |
| **Dev Board**                                | The Opzava-primary developer-operations surface that unifies planning, execution, review, GitHub Issue synchronization, Sprints, Docs, Development evidence, and Releases for the Opzava repository.                                                                                                                                                                                                                                                                                  | The legacy `/tasks` and `/issues` routes; OpenClaw's Control-UI Workboard; customer-support tickets.                                                                                                               |
| **DevTicket**                                | The aggregate owned by the Dev Board bounded context. It holds the governed work contract, workflow state, dependencies, Sprint membership, approvals, assignments, evidence references, and GitHub synchronization identity.                                                                                                                                                                                                                                                         | A GitHub Issue, a generic PM task, an OpenClaw task-ledger entry, or the visual Card.                                                                                                                              |
| **Card**                                     | The visual projection of one DevTicket in Board, List, Sprint, or detail views.                                                                                                                                                                                                                                                                                                                                                                                                       | The persisted aggregate itself; a duplicated Sprint copy.                                                                                                                                                          |
| **Proposal**                                 | A pre-acceptance agent discovery. `AcceptProposal` creates one Backlog DevTicket: verified-link reserves the observed Issue identity before commit; create reserves an intent pending provider identity. `MergeProposal` appends planning evidence and, only when governed work changes, opens a proposed Revision for separate decision; it creates no new DevTicket, GitHub Issue Binding, Mirror Outbox Intent, or provider mutation.                                              | An executable Todo item, an already-created GitHub Issue, proof an asynchronous create succeeded, or a direct governed mutation by `MergeProposal`.                                                                |
| **Revision**                                 | An ID-bearing proposed governed change/diff against exact DevTicket contract and dependency versions, with explicit materiality and decision state.                                                                                                                                                                                                                                                                                                                                   | A Ready Contract Version, a direct mutation, or a Sprint Plan revision.                                                                                                                                            |
| **Sprint Plan Revision Grant**               | An approved exact-version authorization for one coordinated DevTicket contract or dependency change and its atomic Sprint Plan/member-state update (`SprintPlanRevisionGrant` internally).                                                                                                                                                                                                                                                                                            | General Sprint approval, standalone DevTicket authority, or a silent Plan mutation.                                                                                                                                |
| **Sprint Plan Binding Carry-Forward**        | An immutable equivalence record binding an approved nonterminal Sprint member's old and new Ready Contract plus Ready Approval under one exact non-semantic classification.                                                                                                                                                                                                                                                                                                           | A Sprint Plan revision, broad approval reuse, or permission for a material change.                                                                                                                                 |
| **Historical Projection**                    | A read-only classification/projection for imported, frozen, or archived evidence.                                                                                                                                                                                                                                                                                                                                                                                                     | An executable aggregate or proof that current Ready, Review, or Done gates passed.                                                                                                                                 |
| **Governed Document**                        | A stable Dev Board Docs aggregate with one immutable type/path identity, an optional current Approved head, at most one Draft/In Review working head, exact approvals/relations/reliances, and a reversible archive overlay.                                                                                                                                                                                                                                                          | A Markdown file, a Planning Session Log, a mutable wiki page, or proof that a linked workflow gate passed.                                                                                                         |
| **Document Revision**                        | One immutable, canonical UTF-8/LF, content-hashed version of a Governed Document, with predecessor and verified author/source attribution. Lifecycle decisions may approve or supersede it but never change its bytes.                                                                                                                                                                                                                                                                | A DevTicket Revision, a mutable current-head mirror, or navigation metadata.                                                                                                                                       |
| **Document Reliance**                        | A governed consuming-owner binding to one exact Document Revision/hash, stable requirement selectors, relying aggregate/version, purpose, and policy; material replacement makes the exact binding stale and never follows a mutable current pointer.                                                                                                                                                                                                                                 | A Document Relation, backlink, copied text, or broad approval carry-forward.                                                                                                                                       |
| **Planning Session Log**                     | The authoritative append-only planning-decision-ledger stream of attributed questions, recommendations, human decisions, rejected alternatives, unresolved items, and corrections for one session.                                                                                                                                                                                                                                                                                    | A tenth Governed Document type, hidden model reasoning, raw tool output, or the synthesized Planning Brief/PRD.                                                                                                    |
| **Document Owner**                           | The accountable verified human role binding for one Governed Document, versioned independently from any DevTicket. It shapes the document, supplies required approvals or routes them to the type/profile owner, and decides Docs conflicts/archive without inheriting consuming-workflow authority.                                                                                                                                                                                  | A DevTicket Human Owner, document author, approver slot, Incident owner, Sprint owner, Release manager, or permission to approve every document type.                                                              |
| **Document Finalization Authority Envelope** | The exhaustive, single-use type/source authority binding consumed when one immutable Document Revision becomes Approved: exact Document Owner/type/profile decisions, Research author policy, Incident-owner receipt, or applicable Sprint command/owner receipt plus revision/hash/policy/nonce/authorization versions.                                                                                                                                                              | A generic Docs approval, a reusable cross-type receipt, a Document Owner substitute for Incident/Sprint authority, or the Document Revision itself.                                                                |
| **Reliance Invalidation Interruption**       | The DevTicket-owner prepare/contain/finalize record used when a material Governed Document change invalidates exact relied authority during provisioning, start, In Progress, or Blocked. It fences current claim/lease/grant/tunnel/process authority and emits exact containment proof; an ordinary DevTicket or Sprint-member owner transaction then applies Ready/lane/reliance effects without accepting new content.                                                            | A Material Revision Interruption with an AcceptedPendingApplication, a Docs-owned cross-aggregate mutation, an agent-authored Revision, or an Absolute Stop.                                                       |
| **Human Owner**                              | The accountable human who shapes the DevTicket, supplies required human inputs, approves governed changes, and resolves policy or synchronization conflicts.                                                                                                                                                                                                                                                                                                                          | Execution Assignee, Lead Orchestrator, or Reviewer.                                                                                                                                                                |
| **Execution Assignee**                       | The optional single human or agent identity selected to implement a DevTicket. Todo may be unassigned; an atomic claim assigns it before work begins.                                                                                                                                                                                                                                                                                                                                 | Human Owner, Lead Orchestrator, Runner, or Reviewer.                                                                                                                                                               |
| **Lead Orchestrator**                        | The Personal Assistant / coordination role that dispatches, communicates, pauses, escalates, and keeps the human informed without silently granting approval or becoming the Execution Assignee.                                                                                                                                                                                                                                                                                      | The independent Reviewer or the machine-running Runner.                                                                                                                                                            |
| **Reviewer**                                 | The separately configured, fresh local agent-tool/model identity that evaluates a locked commit and evidence package against the approved contract in the local Docker stack.                                                                                                                                                                                                                                                                                                         | Lead Orchestrator, Execution Assignee, or Human Owner.                                                                                                                                                             |
| **Runner**                                   | An explicitly selected execution location and control endpoint: the user's enrolled local machine or an admitted orchestrator/cloud runner. Under an Opzava-owned fenced Execution Lease and governed branch/purpose binding, it owns only signed local process, worktree, branch, command, heartbeat, and checkpoint observations. Provider-native branch/ref/SHA observations are separate correlation inputs. Only the local Runner owns the required local Docker Review access.  | The agent/model identity operating through it; an automatic failover target; an OpenClaw Node or Device; authority to admit/bind/fence its lease or over GitHub-native ref/SHA facts.                              |
| **OpenClaw Node**                            | An OpenClaw-native capability-bearing companion runtime endpoint.                                                                                                                                                                                                                                                                                                                                                                                                                     | A paired Device; a Dev Board Runner, even when one physical machine hosts both.                                                                                                                                    |
| **OpenClaw Device**                          | An OpenClaw-native paired client identity with its own role/token record.                                                                                                                                                                                                                                                                                                                                                                                                             | A Node; a Dev Board Runner, even when one physical machine holds both identities.                                                                                                                                  |
| **Sprint**                                   | One versioned goal and ordered DevTicket plan executed as `autonomous_serial`; at most one Sprint is Active, while Drafts and one Approved/Queued Sprint may exist.                                                                                                                                                                                                                                                                                                                   | A Kanban lane, an Epic, or every collection of ordinary work.                                                                                                                                                      |
| **Ready Contract**                           | The version-bound contract required before Backlog can become Todo: outcome, bounded scope, sad paths, edge cases, acceptance criteria, dependency state, user-level E2E expectations, final behavioral contract, required human inputs, and governance metadata.                                                                                                                                                                                                                     | A title-only task, free-form description, or permanent approval after material edits.                                                                                                                              |
| **Ready Contract Version**                   | One immutable, content-hashed version of a DevTicket's managed Ready Contract and its governance fields.                                                                                                                                                                                                                                                                                                                                                                              | Outside-contract metadata, a mutable description, or a Ready Approval.                                                                                                                                             |
| **Ready Approval**                           | The authoritative human approval bound to one exact Ready Contract Version, dependency set, policy/risk evaluation, Human Owner, and required-input state.                                                                                                                                                                                                                                                                                                                            | A permanent approval, a validation artifact, or a Needs Human Approval Request.                                                                                                                                    |
| **Needs Human Approval Request**             | A bounded, expiring, single-use request for a human decision on one exact eligible action, contract, and policy (`PolicyExceptionRequest` internally).                                                                                                                                                                                                                                                                                                                                | A Ready Approval, reusable authority, or a bypass for an Absolute Stop.                                                                                                                                            |
| **Blocked Episode**                          | The required reasoned record for one DevTicket in Blocked, including prior lane, condition, checkpoint, containment, notification, and a truthful closure: resolved with proof or superseded with unresolved refs preserved.                                                                                                                                                                                                                                                          | A dependency lock, free-form status string, or false claim that an obsolete condition resolved.                                                                                                                    |
| **Dependency Edge**                          | A versioned directed relation `dependent → blocker`; the dependent cannot be claimed until the blocker is admitted Done.                                                                                                                                                                                                                                                                                                                                                              | A Blocked Episode, copied blocker status, or display-only link.                                                                                                                                                    |
| **Claim Attempt**                            | One governed admission attempt binding an eligible claimant and Runner to an exact Ready Approval before trusted execution start.                                                                                                                                                                                                                                                                                                                                                     | Proof that work started, reusable authority after failure, or an Execution Lease.                                                                                                                                  |
| **Claim Requested**                          | A durable internal start-request intent created with Ready approval, binding the original verified requester/source, intended claimant, authorization and Runner capability versions, and exact admission gates until a worker consumes, cancels, or supersedes it (`ClaimRequested` internally).                                                                                                                                                                                     | A Claim Attempt, worker-owned claimant authority, or permission to start after authorization/gate drift.                                                                                                           |
| **Execution Lease**                          | Runner-scoped fenced execution authority bound to one DevTicket, Ready Contract Version, worktree/branch/SHA, capacity reservation, nonce scope, and expiry.                                                                                                                                                                                                                                                                                                                          | Execution Assignee identity, lane, Ready Approval, or merge permission.                                                                                                                                            |
| **Runner Containment Request**               | A durable idempotent Runner checkpoint-plus-stop-or-quarantine request bound to one containment owner, Execution Lease, old/advanced fence, process registration, worktree, action, and one-use nonce (`RunnerContainmentRequest` internally).                                                                                                                                                                                                                                        | Proof that a process stopped, a second containment finalizer, or safety inferred from fencing.                                                                                                                     |
| **Lease Credential Access Grant**            | A safe Runner/Execution Admission record bound to one Execution Lease and exact approved named-secret reference IDs, containing broker/local grant refs, lifecycle versions, and activation/revocation confirmations—never secret values (`LeaseCredentialAccessGrant` internally).                                                                                                                                                                                                   | The underlying secret/credential, Secrets authority, or reusable access outside the lease.                                                                                                                         |
| **Claim Admission Deferred**                 | A durable future-start wait created when an otherwise requested claim cannot pass admission, with a terminal original command and monotonic retries (`ClaimAdmissionDeferred` internally).                                                                                                                                                                                                                                                                                            | A Claim Attempt, Execution Lease, reserved capacity, or reusable original command.                                                                                                                                 |
| **Pre-Start Admission Loss**                 | A contained failed admission detected while a Claim Attempt is still `credential_provisioning`, before any Runner start delivery exists; it preserves deterministic no-start/no-process proof and grant/tunnel revocation confirmations until safe resource release (`PreStartAdmissionLoss` internally).                                                                                                                                                                             | A Blocked Episode, ambiguous `start_pending` loss, or evidence that execution began.                                                                                                                               |
| **Start Rejection Containment**              | A durable containment record created when an authenticated signed rejection proves a `start_pending` Claim Attempt started no process; it holds capacity, worktree, claim-created assignment, and grant/tunnel revocation confirmations until its named finalizer (`StartRejectionContainment` internally).                                                                                                                                                                           | Pre-Start Admission Loss, ambiguous execution loss, a Blocked Episode, or direct release on rejection.                                                                                                             |
| **Execution Binding Carry-Forward**          | An immutable equivalence record binding original execution authority/evidence to an exact current Ready Contract Version and Ready Approval after an approved non-semantic correction.                                                                                                                                                                                                                                                                                                | Mutation of the original Execution Lease, permission expansion, or proof of material equivalence.                                                                                                                  |
| **Review Handoff**                           | A versioned containment record for one exact frozen candidate after admission to Review and before reviewer launch (`ReviewHandoff` internally); states are `prepared`, `cancelling`, `finalized`, `cancelled`, `superseded`, or `failed`, with terminal disposition evidence preserved.                                                                                                                                                                                              | Review membership, reviewer authority, or reusable implementation authority.                                                                                                                                       |
| **Review Admission Retry**                   | A durable future Review-admission job bound to original requester/source authorization and exact checkpoint/SHA/equivalence lineage, with monotonic attempt keys and one Slack notification identity (`ReviewAdmissionRetry` internally).                                                                                                                                                                                                                                             | A Review Handoff, worker-owned submission authority, or permission after authorization/evidence drift.                                                                                                             |
| **Review Containment Proof**                 | An authenticated #229-owned fact bound to one finalized Review Handoff and an exact Material Revision Interruption or Absolute Stop containment requirement, proving the stale Reviewer lease/process, Docker session/lease, preview tunnel, and evidence authority are stopped, closed, or reconciled.                                                                                                                                                                               | Rewriting the finalized Review Handoff, implementation containment, or permission to exit Review/resolve a stop early.                                                                                             |
| **Review Exit Containment Proof**            | An authenticated #229-owned fact required for ordinary changes-requested or Done exit, bound to the exact review run/result and proving its Reviewer process/lease, shared Docker lease/session, test grants/tunnel, and artifact/evidence writers are stopped, closed, or reconciled (`ReviewExitContainmentProof` internally).                                                                                                                                                      | A Review verdict, Material Revision/Absolute Stop proof, or permission to decrement Review WIP early.                                                                                                              |
| **Material Revision Interruption**           | The durable pending prepare/finalize record created when an accepted material Revision meets credential provisioning, starting, active, execution-unknown, or finalized Review authority; it fences or requests containment and holds resources/lane exit until safe finalization.                                                                                                                                                                                                    | A completed Revision, a database fence that proves process containment, or an ordinary Backlog edit.                                                                                                               |
| **Todo Ordering Band**                       | The derived Todo bucket ordered first by `reviewReworkPlacement` (`blocking_top`, `planned`, `ordinary_bottom`), then dependency criticality and Priority; rank is mutable only inside that exact bucket.                                                                                                                                                                                                                                                                             | A lane, user-editable override, approval, or permission to reorder across tiers or Priority.                                                                                                                       |
| **App Registration Ref**                     | The platform-owned GitHub App registration/configuration record, including provider App/client identity, public configuration and rotation versions, vault-only secret refs, and global access audit. Tenant records may retain only opaque public configuration/rotation versions, never its secret refs or secret-ref versions.                                                                                                                                                     | A tenant GitHub Installation Binding, a browser-visible secret reference, or a standing installation token.                                                                                                        |
| **Installation Association Proof**           | The durable one-time setup proof binding an authenticated Admin, provider user/account, exact installation/repository, authorization/config versions, provider-issued access/refresh expiries, cleanup-operation receipts/state, local-zeroing state, and consumed/expired/denied outcome. It never stores token values. A refresh-credential revoke `202 Accepted` is not confirmed revocation; absent later documented proof, its quarantined handle remains until recorded expiry. | A GitHub Installation Binding, App authentication alone, or a reusable GitHub user credential.                                                                                                                     |
| **GitHub Installation Binding**              | The tenant-scoped binding to one provider-verified GitHub App installation and immutable account identity, with status, granted permission/event versions, lifecycle facts, and only opaque public App configuration/rotation versions. It contains no installation access token or platform secret-ref identity/version.                                                                                                                                                             | App Registration Ref, an OAuth/PAT connection, a callback `installation_id` claim, cached token, provider workflow authority, or proof repository capability is healthy.                                           |
| **GitHub Repository Binding**                | The tenant-scoped, provider-verified binding to the one admitted v1 production repository by immutable repository ID/node ID and its GitHub Installation Binding; owner/name are mutable routing/display data updated only after provider verification.                                                                                                                                                                                                                               | A caller-provided URL/owner/name, a second production repository, or a GitHub Issue Binding.                                                                                                                       |
| **GitHub Issue Binding**                     | The canonical unique reservation for one DevTicket: a verified-link path reserves the known immutable repository/Issue identity before acceptance, while a create path reserves one stable create intent pending later provider confirmation. Origin and its create-or-link correlation survive pending, confirmed, archived, and historical states.                                                                                                                                  | A URL asserted by a caller, proof that a pending create succeeded, a disposable mirror projection, or a GitHub workflow decision.                                                                                  |
| **Webhook Inbox Receipt**                    | The durable, deduplicated, Secret-Safe tenant record of one authenticated GitHub delivery, keyed by an opaque public App configuration key plus delivery ID and carrying exact raw-body hash, schema classification, admitted provider identities, safe normalized payload ref, opaque public rotation version, and disposition—never a platform App registration/secret-ref identity or version.                                                                                     | Persisted raw webhook content, global event order, or authority to mutate a DevTicket directly.                                                                                                                    |
| **Mirror Outbox Intent**                     | One durable, fenced provider-mutation intent keyed by the originating Opzava event, exact operation/target/request hash, claim generation, numbered attempt, schedule, unknown-outcome state, and provider confirmation.                                                                                                                                                                                                                                                              | Proof of exactly-once provider mutation, a mutable worklog, or permission to blind-retry an ambiguous effect.                                                                                                      |
| **Provider Observation**                     | An append-oriented, source-versioned safe observation of a provider object/ref and its identity, actor/App, value digests, fetch or delivery epoch, and observed/recorded times.                                                                                                                                                                                                                                                                                                      | An Opzava workflow decision, a Mirror Shadow, or truth inferred from an unverified callback.                                                                                                                       |
| **Mirror Shadow**                            | The last mutually confirmed per-field synchronization base binding an Opzava version/event and exact provider observation/value digest. Reconciliation compares this base with current Opzava and GitHub values; it never creates new authority, assumes provider compare-and-swap, or advances before provider confirmation.                                                                                                                                                         | A whole-object cache, latest-timestamp winner, webhook delivery order, or permission to overwrite concurrent changes.                                                                                              |
| **Reconciliation Epoch**                     | One fenced snapshot traversal for a named integration scope, with generation/claim, cursors/pages, start/end observations, completeness/gaps, and convergence result.                                                                                                                                                                                                                                                                                                                 | A webhook delivery sequence, proof of absence from one page pass, or permission to retry an ambiguous identity-creating mutation.                                                                                  |
| **Sync Conflict**                            | The versioned durable same-field divergence record binding base Mirror Shadow, exact Opzava/provider versions and safe values/refs, blocking class, decision state, and provider-confirmed resolution. Contract, dependency, assignment, or approval conflicts pause affected execution until Human Owner resolution in Opzava.                                                                                                                                                       | A harmless different-field auto-merge, temporary integration-health failure, last-write-wins rule, or integration-worker workflow authority.                                                                       |
| **Integration Health Snapshot**              | A scoped, policy-versioned evaluation of GitHub App, installation, repository, permissions, token mint, webhook, rate, outbox, and reconciliation dimensions with evidence and last-good reference.                                                                                                                                                                                                                                                                                   | A single `/user` probe, permanent connection truth, or a bypass around an Absolute Stop.                                                                                                                           |
| **Actions Request Receipt**                  | The atomic OIDC-origin receipt binding issuer/token ID, repository/workflow/run/ref/SHA, allowed family, family-specific target/provider evidence, one-use nonce, request hash, disposition, and exactly one downstream result: Provider Observation, DevTicket command receipt, or owning-domain Needs Human Approval Request/command receipt.                                                                                                                                       | A label/comment, reusable credential, deploy/rollback/release command, or authority beyond native check/deployment fact append, `ready.validate`, and an eligible failed-policy-gate Needs Human Approval Request. |
| **Authorized Git Ref Update**                | The durable exact-ref push record binding one admitted remediation lease/purpose, ref, expected old SHA, intended new SHA, bundle hash, nonce/expiry, broker claim/fence, provider attempt, reconciliation state, and confirmation; it never contains a token.                                                                                                                                                                                                                        | General GitHub write authority, a duplicate remediation run, or proof of success from a lost provider response.                                                                                                    |
| **GitHub Disconnect Saga**                   | The durable idempotent disconnect state machine binding one installation/repository binding generation, outbound fence/drain proof, exact provider uninstall/revocation outcome, local cleanup, retained history, and reconnect eligibility.                                                                                                                                                                                                                                          | Deleting a local ref, an unaudited best-effort uninstall, or permission to reconnect while provider outcome is unknown.                                                                                            |
| **Absolute Stop**                            | An unbypassable scoped gate for suspected secret exposure or unhealthy/unverifiable GitHub integration; it blocks admission and contains affected execution until verified remediation and authorized resolution.                                                                                                                                                                                                                                                                     | A Needs Human Approval Request, ordinary Blocked reason, or policy exception.                                                                                                                                      |
| **Secret-Safe Ingress**                      | The authorization-gated, pre-persistence scan for every content-bearing or free-text command field; suspected-secret raw values never persist and only a safe ref may enter the Absolute Stop security path.                                                                                                                                                                                                                                                                          | Authentication, authorization, or a scanner an unauthorized caller may invoke or probe.                                                                                                                            |
| **GitHub Mirror**                            | The durable synchronized GitHub Issue representation of an accepted DevTicket, including managed labels, readable contract block, comments, milestone/worklog history, and native delivery links. Opzava owns workflow and Execution Lease/binding/fence state; GitHub owns its native issue number/URL and provider PR, branch/ref/SHA, commit, check, repository-review, and merge facts; Runner-signed local execution observations remain separate.                               | A second independent workflow authority, a disposable cache, or authority over Opzava lease/binding state or Runner observations.                                                                                  |
| **Runner execution ledger**                  | The append-oriented operational record of signed local process, worktree/local-branch, command, receipt, monotonic-sequence, heartbeat, checkpoint, Docker, and reconnect observations. Observations carry references to Opzava-owned lease, fence, and command-nonce records but never own or duplicate those lifecycle records.                                                                                                                                                     | Planning rationale, accepted Card activity/history, Opzava-owned admission/lease/grant/binding/fence/containment/release state, or the GitHub synchronization/outbox/conflict ledger.                              |
| **Incident**                                 | A separate operational aggregate/projection with lifecycle `Detected → Triaged → Mitigating → Monitoring → Resolved → Postmortem`; permanent remediation is a linked Bug or Technical Task DevTicket.                                                                                                                                                                                                                                                                                 | A Sprint-eligible DevTicket type or an ordinary Board lane.                                                                                                                                                        |
| **Release**                                  | The separate Opzava aggregate that governs desired promotion lifecycle, immutable manifest, approvals, fenced deployment attempts, supersession/cancellation, rollback decisions, and Release evidence after DevTickets are Done.                                                                                                                                                                                                                                                     | A DevTicket lane; a GitHub Release; current environment health; an Incident.                                                                                                                                       |
| **Release Candidate**                        | An immutable sealed identity `vX.Y.Z-rc.N` bound to one candidate SHA/tree and one Release Manifest hash.                                                                                                                                                                                                                                                                                                                                                                             | A mutable Draft, a branch name, a local Review image, or the stable GitHub Release.                                                                                                                                |
| **Release Manifest**                         | The immutable build-once contract binding candidate source/tree, exact work composition, per-service OCI digests, trusted provenance/signatures/SBOM, deployment/config hashes, migrations/compatibility, named secret refs, checks, and evidence.                                                                                                                                                                                                                                    | A mutable Compose file, environment values, a provider deployment request, or secret storage.                                                                                                                      |
| **Trusted Build Request**                    | The immutable one-build identity bound to an exact frozen Draft revision, RC, source/tree, composition/config fingerprint, builder/registry, and idempotency input. Unknown reconciles this same request; it never starts a parallel rebuild. A terminal failed/no-artifact request may be abandoned only by the explicit atomic command that creates a successor revision and new RC reservation.                                                                                    | A mutable build configuration, CI retry with different input, or provider build log.                                                                                                                               |
| **Release Approval**                         | An immutable human decision bound to exact actor/role, Release/candidate/manifest, environment, evidence, action, nonce, expiry, policy, and reason. Staging and Production Approvals are distinct.                                                                                                                                                                                                                                                                                   | A `NeedsHumanApproval` exception, GitHub label/Action, Slack message, or durable blanket permission.                                                                                                               |
| **Deployment Attempt**                       | One fenced append-only attempt of kind `Staging`, `Production`, `Rollback`, or `RestoreStaging`, with provider observations and an exact immutable manifest target.                                                                                                                                                                                                                                                                                                                   | Release lifecycle, provider request acceptance, or evidence that deployment succeeded.                                                                                                                             |
| **Deployment Lease**                         | Environment-scoped authority for one Deployment Attempt with a monotonically increasing fence. Expiry revokes the worker but never frees the fence or admits new mutation without trusted reconciliation.                                                                                                                                                                                                                                                                             | Staging Occupancy, provider operation state, or an automatic timeout fallback.                                                                                                                                     |

## Legacy route note

The currently implemented `/tasks` and `/issues` routes, their existing Task aggregate/projection,
and their MCP/issue-adapter behavior remain **legacy as-built code until the migration is
completed**. They describe current runtime reality, not the target product vocabulary. New product
design and replacement implementation follow PRD-019, ADR-017, the Dev Board decision ledger, and
the migration manifest; do not use Q17 to extend the legacy model.
