# Opzava 2.1.0

Released: 2026-06-22

Opzava 2.1.0 is the milestone-2 release. It follows a full system-map audit of the opzava product
layer — every architectural claim re-verified and logged — and turns that audit into a sequenced
remediation that closes all headline parity findings. The headline capability: the one live external
side effect, the **campaign email send**, is now turned **on** behind a complete safety boundary
(approval-gated, exactly-once, rate/cost-limited, env-only secrets). All changes are
backward-compatible.

## Highlights

### Approval-gated live campaign send (Resend)
- An admin-triggered campaign run now drains the send queue through the provider guard. Each send
  leaves an **external-call receipt + redacted audit event** and is **provider-level exactly-once**
  (idempotency lookup + atomic reserve-before-execute).
- A send is never autonomous: it requires a **granted, bounded-expiry approval** recorded against the
  campaign and a configured `RESEND_API_KEY`. No approval ⇒ no adapter call.
- **Provider rate/cost limits are enforced** on this path — `requestsPerMinute` plus hourly/daily USD
  budgets fail closed before a send, not merely settable.

### Secrets out of the database
- Provider credentials are now **environment-only** ([ARD 0008](../ard/0008-secret-storage-and-resolution.md)):
  resolved from `process.env` via `SecretReference`s through a resolver seam. No cleartext provider
  secrets are stored at rest; the connections UI shows an env-secret note instead of secret inputs.

### Unified cross-engine surfaces
- Following [ARD 0007](../ard/0007-engine-separation-and-surface-unification.md) (*separate engines,
  unified surfaces*), `GET /api/ops/costs` and `GET /api/audit` now return a `unified` summary that
  merges the opzava engine with the inherited (Engine A) cost/audit — pure projections, so neither
  engine imports the other. A governance gate statically enforces the one-way engine boundary.

### Operability
- **Admin runtime settings API** — `GET/PUT /api/ops/admin-settings` (validated, versioned, audited;
  stores `SecretReference`s, never secret values).
- **Background runner maintenance** — crashed-lease recovery + data retention now run on a timer
  beside the inherited scheduler (the two timers coexist; nothing merges).
- **Centralized log shipping** to an external aggregator — `LOG_SHIP_ENABLED` / `LOG_SHIP_ENDPOINT` /
  `LOG_SHIP_MIN_LEVEL` (off by default, fail-open).

### Product-integrity gates
- **Content quality gates** are now enforced: a WordPress draft can only be produced when the
  fact-check, brand-review, and anti-slop verdicts all *passed*. A failed verdict halts the run at the
  single chokepoint both orchestrators call.

## Full Changelog

### Added
- Approval-gated live campaign email send (Resend) — receipt + redacted audit + provider-level
  exactly-once; requires a granted bounded approval and `RESEND_API_KEY`; never autonomous
- Provider rate/cost limit enforcement on the live send path (fail-closed)
- Unified cross-engine cost (`GET /api/ops/costs`) and audit (`GET /api/audit`) surfaces
- Admin runtime settings API — `GET/PUT /api/ops/admin-settings`
- Background runner maintenance (lease recovery + data retention) on a timer
- Centralized log shipping to an external aggregator (env-gated, fail-open)
- Content quality gates — fact-check / brand-review / anti-slop must pass before a draft

### Changed
- Provider credentials are environment-only (ARD 0008) — no cleartext provider secrets at rest
- Model ids/pricing centralized into `src/lib/model-config.ts`, enforced by the `no-hardcoded-models`
  governance gate across 12 files

### Fixed
- Campaign send is hard-gated by a recorded, bounded approval (no hardcoded send flag)
- Natural-language cron parser honours all five cron fields (no over-firing)
- CI quality gate hardened: resilient E2E env prep, governance gates enforced on merge, dir-name and
  MCP-brand assertions corrected, GitHub Actions trimmed for cost

### Internal
- System-map architecture ledger (`docs/architecture/system-map/`) — second verification pass; all
  zones verified, every corrected claim logged in the verification register
- ARDs 0007 (engine separation, unified surfaces) and 0008 (environment-based secrets)
- Engine-boundary governance gate (one-way, negative-controlled)
- Scoped mutation-testing harness (Stryker) over the safety-critical units
