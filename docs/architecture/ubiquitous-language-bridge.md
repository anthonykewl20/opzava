# Ubiquitous-language bridge (CONTEXT.md to code)

This is the rosetta stone so every architecture doc uses the canonical CONTEXT.md term and points at the right code.
CONTEXT.md is authoritative for terms; this file maps each term to the Module, Seam, and Adapter where it lives today.
Where a term is not yet reflected in code, the row is marked **planned/aspirational** and names the slice that will land it.

Read this alongside `ARCHITECTURE.md` (bounded contexts and the ports catalog) and the ADRs cited per row.
Design detail lives there; this file stays a map from word to file path.

## Vocabulary used in this file (codebase-design terms, used exactly)

- **Module** = anything with an Interface and an Implementation (a package, an app, a port+adapter pair).
- **Interface** = all a caller must know: signature plus invariants plus ordering plus error modes.
- **Implementation** = the concrete behavior behind the Interface.
- **Seam** = where an Interface lives (a port file, an RPC boundary, an ACL).
- **Adapter** = a concrete thing satisfying an Interface at a Seam.
- **Depth** = deep means much behavior behind a small Interface; shallow means the Interface is nearly as complex as its Implementation.
- **Leverage** = how much behavior one Interface change unlocks for free.
- **Locality** = how far a change stays inside one Module without ripening across Modules.
- Heuristics used below: the deletion test (delete it; what breaks?), the interface is the test surface, and one Adapter is a hypothetical Seam while two Adapters make a real Seam.

## Aspirational or partially-landed terms (consolidated)

- **User dashboard** has no Module yet; CRM currently has no surface and returns there when rebuilt. Ask Opzava remains a bounded user surface.
- **Ask Opzava** (user-facing) is not implemented; the current `/ask-opzava` route is the admin Ask surface carrying known naming debt.
- **Rung-2 customization** (`mainframe/extensions/opzava-*`) is not yet used; the ladder currently sits at rung-0 and one rung-3 patch.
- **Dynamic per-tenant Gateways** are deferred under the ADR-002 amendment; only the static Platform Gateway runs.
- **Projection worker** is scaffolded but empty (`apps/workers/src/projections/.gitkeep`); projections are rebuildable caches today only via ad-hoc outbox jobs and snapshot re-reads.

## Seams and depth worth noting for other docs

- The single anti-corruption Seam to OpenClaw is `OpenClawGatewayPort` in `packages/ports/src/openclaw-gateway.ts`.
- That Interface is currently SHALLOW and partial: it exposes only `startAssistantStream`, `getEffectiveTools`, and `getHealth` (lines 114 to 118).
- `ARCHITECTURE.md` describes that Seam as covering sessions, streams, tasks, channels, logs, diagnostics, usage, cron, approvals, skills, memory, and Workboard projections; most of that breadth is planned/aspirational, so cite the implemented methods, not the catalog, when describing live behavior.
- Two Adapters already meet that Seam in part (the broker operator client and the worker admin client via the same port package), which makes it a real Seam rather than a hypothetical one even at current depth.
- The two-token model is the cleanest example of Locality in the codebase: the credential split keeps a hot-path compromise inside one tenant Gateway and out of config or pairing.
