## Overview

## Cross-cutting notes
- The two-token discipline is enforced on the hot path by expected scopes `operator.write` and `operator.approvals`, by rejecting non-paired-device manager routes in the operator client, and by sending paired-device auth in the connect frame rather than shared-token auth (`apps/gateway-broker/src/acl/openclaw/protocol.ts:4`, `apps/gateway-broker/src/acl/openclaw/operator-client.ts:291`, `apps/gateway-broker/src/acl/openclaw/operator-client.ts:772`).
- Tenant-derived routing is enforced by runtime route creation from config tenant id, manager lookup by route id, tenant-keyed client storage, and operator-client rejection when the acting principal tenant does not match the route tenant (`apps/gateway-broker/src/runtime/server.ts:21`, `apps/gateway-broker/src/routing/connection-manager.ts:121`, `apps/gateway-broker/src/routing/connection-manager.ts:172`, `apps/gateway-broker/src/acl/openclaw/operator-client.ts:343`).
- Idempotency and replay are concentrated in the operator client by requiring an idempotency key for side-effecting requests, adding it only to side-effecting Gateway calls, deriving a fallback run ref from it, and letting the fake gateway replay the same run for the same idempotency key (`apps/gateway-broker/src/acl/openclaw/operator-client.ts:414`, `apps/gateway-broker/src/acl/openclaw/operator-client.ts:794`, `apps/gateway-broker/src/acl/openclaw/operator-client.ts:814`, `apps/gateway-broker/src/acl/openclaw/fake-gateway.ts:408`).
- Circuit-breaking is split between operator-client connection-level degradation and manager tenant-level backoff, so future changes need tests at both the manager Interface and the operator client Interface (`apps/gateway-broker/src/acl/openclaw/operator-client.ts:246`, `apps/gateway-broker/src/acl/openclaw/operator-client.ts:291`, `apps/gateway-broker/src/routing/connection-manager.ts:61`, `apps/gateway-broker/src/routing/connection-manager.ts:198`).
- Opaque-ref mapping is performed at the HTTP adapter when accepting `sessionRef` and in the operator client when returning OpenClaw session and run refs (`apps/gateway-broker/src/internal/http-server.ts:178`, `apps/gateway-broker/src/acl/openclaw/operator-client.ts:157`, `apps/gateway-broker/src/acl/openclaw/operator-client.ts:165`, `apps/gateway-broker/src/acl/openclaw/operator-client.ts:439`).
- Realtime hub is unverified as a runtime Module because `apps/gateway-broker/src/realtime` contains only `.gitkeep`, while the stream hub behavior today is `AsyncQueue` inside the operator client (`apps/gateway-broker/src/rpc/async-queue.ts:1`, `apps/gateway-broker/src/acl/openclaw/operator-client.ts:369`).
- Broker Docker runtime control is unverified by file:line in `apps/gateway-broker/src` because the source files read for this app contain no Docker runtime import or Docker command, while the only Docker-named file under the app is the image build `Dockerfile` outside `src` (`apps/gateway-broker/Dockerfile:1`, `apps/gateway-broker/src/runtime/server.ts:1`, `apps/gateway-broker/src/acl/openclaw/operator-client.ts:20`).
