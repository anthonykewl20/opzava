# apps/web - Next.js App Router BFF + admin dashboard
> Part of the Opzava architecture (see ../README.md).
> Vocabulary: codebase-design.

## Overview
The server/client split is disciplined: server actions live under `app/(app)/*/actions.ts` with `"use server"` and browser Modules live under `components/*` with `"use client"` (`apps/web/app/(app)/connections/actions.ts:1`, `apps/web/app/(app)/tasks/actions.ts:1`, `apps/web/components/tasks/tasks-board.tsx:1`, `apps/web/components/connections/model-providers-panel.tsx:1`).

## Modules

### App shell and routing gate - `apps/web/app/layout.tsx`, `apps/web/proxy.ts`, `apps/web/next.config.ts`, `apps/web/instrumentation.ts`
- **Interface (the seam):** The Interface is `metadata`, `RootLayout`, `proxy`, and `config`, where callers must know that all non-static, non-auth routes pass through setup and session routing before App Router rendering (`apps/web/app/layout.tsx:7`, `apps/web/app/layout.tsx:23`, `apps/web/proxy.ts:17`, `apps/web/proxy.ts:44`).
- **Behind the seam (implementation):** The Implementation sets the theme bootstrap script, imports runtime env only in the node runtime, and redirects unauthenticated or pre-setup traffic to `/setup` or `/login` (`apps/web/app/layout.tsx:12`, `apps/web/instrumentation.ts:1`, `apps/web/proxy.ts:19`, `apps/web/proxy.ts:41`).
- **Seams:** The external Seam is the Next.js routing hook, and the internal coupling is to `getAppSessionContext` plus `isFirstOwnerSetupComplete` (`apps/web/proxy.ts:3`).
- **Deepening opportunity:** none - already correctly shallow for framework bootstrap.
