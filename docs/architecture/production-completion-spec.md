# Opzava Production-Completion Spec (3-Pass Merged — DECISIVE)

**Status**: AUTHORITATIVE. Every item below is DONE (this session) / DO-NOW / DEFER (with a decided reason). Nothing is left open-ended.
**Scope**: Merge of Pass 1 (defect hunt), Pass 2 (depth/scale sweep), and this-session completion work.
**Classification rule applied**: DO-NOW = real defects (P0-P2, effort S/M) + cheap high-value refactors (S) + the lightweight realtime-observability metrics feature. DEFER = scale-only (not a defect at internal-team scale), infra-dependent (multi-instance / migration requiring design), or large refactors (L) needing design. When uncertain, DEFER-with-reason.

## Executive Verdict

The realtime/chat spine is now durable (transactional outbox, idempotency, jittered SSE retry, resync sentinel, graceful drain, prune off the broadcast path). What remains is **two clusters**:

1. **DO-NOW (44 items)** — verified defects and cheap refactors. The most important are: the runner exactly-once hole on transient provider failure (duplicate email), the runner's un-jittered/no-settings retry policy, the dead claim-guard in `autoRouteInboxTasks`, the `/api/super` and approval self-approve authorization gaps, the macOS-only `/api/local/terminal` (broken on the documented Linux platform), the `station-doctor.sh --port` bug, the local-vs-CI parity-gate drift, the logger that ships raw secrets, the always-empty PTY session list (split-brain), and the dead `resyncNeeded` consumer that makes the realtime UI silently stale after any retention gap. Plus the lightweight metrics feature (`GET /api/ops/chat-metrics`) that makes the SSE/runner hot paths observable.

2. **DEFER (28 items)** — multi-tenant/workspace_id migration of the opzava Engine B tables + audit_log + search/claude sessions (L, needs design), the never-started background job-drain worker (P0 data loss but L + needs the daemon-runtime seam wired), the request-context AsyncLocalStorage seam (L), the panel data-layer refactor (L), the MCP single-key→per-agent scoping (L, security architecture), and scale-only items (WAL-bloat, per-process prune coordination, dedup-Set 500-cap, etc.) that are not defects at internal-team scale.

The DO-NOW set is bounded, self-contained, and safe to auto-execute. The DEFER set is *decided*, not deferred out of indecision — each carries the precondition that would promote it.
