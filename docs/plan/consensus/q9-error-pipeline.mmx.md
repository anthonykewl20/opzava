**1) Error SOURCES + ingestion — DECISIVE PICK:** Build a thin `ErrorEvent` ingest endpoint (BFF) accepting from 4 producers: (a) in-process Next.js `error.tsx` + `route.ts` reporters (browser+server, with route id), (b) broker/ACL ingestion errors from the Workboard adapter, (c) OpenClaw ACL pulls — scheduled `logs.tail` (cursor per gateway), `diagnostics.stability`, task-ledger `failed/timed_out/cancelled`, Workboard flags, gateway usage spikes, (d) tenant/customer reports via a minimal support form. All funnel into ONE normalized `Incident` (tenantId nullable, projectId nullable, agentId nullable, gatewayId nullable, source enum, severity, fingerprint, raw JSONB). No separate per-source models.

**2) FINGERPRINT/DEDUP:** SHA-256 of `service|route|exception-type|normalized-message-95%-token-overlap`. Card-creation thresholds: (a) suppress until count ≥ N within window W (default 3 / 5min), (b) OR severity=critical → immediate, (c) cooldown 30min per fingerprint before re-card, (d) hour-bucket rate-cap 10 new cards/tenant/hr. Increment count, update `lastSeen`; one card per fingerprint lifetime, reopen on recurrence post-resolve.

**3) ADMIN BOARD — DECISIVE PICK:** Distinct **platform-ops board** (Opzava-owned, `board.tenantId = NULL`, `isPlatform = true`) for app+infra+all-gateway errors. Tenant boards receive only errors tagged to that tenant (`tenantId IS NOT NULL`, PII-stripped). Cross-tenant info NEVER leaves platform board — enforced by row-level RLS + query-layer guard. A `visibility` enum (`platform_only|tenant_visible|tenant_redacted`) on `ErrorGroup` is the single switch.

**4) REMEDIATION LOOP — DECISIVE PICK:** Triage card → assistant reads `logs.tail` + `diagnostics.stability` via ACL → proposes RemediationAction with blast-radius class → **approval gate required for class ≥ medium** (restart-gateway, re-dispatch, re-provision). Default autonomy = `low` (notify + draft only). Every action: dry-run-first, idempotency-key, audit row in `RemediationAction` (actor=admin-token, before/after state, ACL calls). Class `destructive` (re-provision, drain-queue) always requires 2-step human confirm.

**5) BUY vs BUILD — DECISIVE PICK:** **Self-host GlitchTip** (lean, Sentry-API compatible, single Postgres DB, ~150MB RAM) for raw capture + symbolication + grouping. Our layer adds: tenant/project tagging, platform-board routing, remediation hooks, admin-token ACL. We do NOT build symbolicator/source-map stack ourselves. GlitchTip `project` = our `ErrorGroup.fingerprint` mapping.

**6) BIGGEST SAD PATH + INVARIANT:** **Logger-itself fails / dead-letter loop** — when the reporter crashes, errors vanish silently and the admin-card pipeline goes blind. **Invariant:** `errors_ingest_deadletter` table is the absolute sink; GlitchTip webhook + in-process queue both write here on failure. A watchdog card (heartbeat-driven, never suppressable) fires if no ErrorEvent lands for 5min. Secondary invariant: **no error payload may leave its tenant scope without passing the redaction filter** — enforced in one `redact(payload, visibility)` function, called at ingest boundary, not at read time.

**Parity + lean-ops one-liner:** Reuse OpenClaw ACL (`logs.tail`, `diagnostics.stability`, task ledger, Workboard flags) as our only observability source for gateway-side; GlitchTip handles app-symbolication; one Postgres schema, one admin token, one board, one redaction function.
