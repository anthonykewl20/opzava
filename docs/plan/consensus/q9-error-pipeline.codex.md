# Q9 Error -> Admin Card Pipeline

**Decision.** Build an Opzava-owned Notifications/Admin-Observability context in Postgres. The aggregate root is `ErrorGroup`, the normalized Incident: `fingerprint, severity, count, firstSeen, lastSeen, status=open|ack|mitigating|resolved|muted, tenantId?, projectId?, agentId?, gatewayId?, visibility`. Children: `ErrorEvent(source, occurredAt, sanitizedPayload, openClawRef?)`, `RemediationAction(action, blastRadius, approvalId?, idempotencyKey, dryRun, result, actor=admin-token)`, `AlertRoute(scope, destination, thresholds)`. The first active group creates or updates one Opzava `PmCard` on the platform ADMIN board; the card is a projection, not the aggregate.

**Projection mapping.** The broker/ACL owns all OpenClaw reads. It projects Next.js/BFF/broker exceptions plus Gateway signals into `ErrorEvent`: `logs.tail` cursors for structured error/warn lines; `tasks.list/get` and task audit findings for `failed|timed_out|lost|cancelled`, stale queued/running, and delivery failures; `diagnostics.stability` for bounded liveness, queue/session, payload-large, memory, channel/plugin/tool categories; `health` snapshots/events for degraded gateways/agents; Workboard `cards.diagnostics` and notification cursors for no heartbeat, blocked, repeated failures, start failures, and loose-session links; protected Prometheus text metrics for threshold-only signals such as tool/model/webhook/message-delivery errors, session stuck/recovery, liveness, memory pressure, and series drops. Per Q4, snapshots are truth, WS/events are hints; the broker writes projection rows and domain outbox events idempotently.

**Dedup/card storms.** Fingerprint = SHA-256 of `scope|source|service|route|gatewayId|agentId|taskKind|tool/channel/plugin|errorClass|normalizedMessage|topFrame`, with run/task/session/request ids, URLs, emails, tokens, and literals stripped. Critical creates immediately; otherwise require 3 events/5 min, one active card per fingerprint+scope, 30 min reopen cooldown, and caps of 5 new platform cards/gateway/hour plus 20/tenant/day. Excess increments counters and appends digest comments, not new cards.

**Admin board and visibility.** The ADMIN board is Opzava PM storage (`tenantId = NULL`, `isPlatform=true`) spanning app, infra, and all tenant Gateways. It is not OpenClaw Workboard, which remains Gateway-local agent-work and a diagnostics source. Tenant-visible error views are separate redacted projections where `tenantId` is set and `visibility != platform_only`; RLS plus a query guard forbid tenant reads of platform rows or other tenants.

**Ask Admin Opzava.** The admin assistant reads the card, then uses ACL reads (`logs.tail`, `diagnostics.stability`, `tasks.get`, `health`, Workboard diagnostics, metrics) to draft a `RemediationAction`. Low tier may label/comment/request more data. Default for mutation is draft-only: cancel/re-dispatch one task or restart one Gateway needs human approval; re-provision, config/secret changes, queue drains, bulk actions, and cross-tenant operations require two-step confirmation. Every approved call uses the admin/provisioning token, one-tenant blast radius, dry-run where supported, idempotency key, and immutable audit.

**Buy/build.** Pick lean built-in incident domain now, not self-hosted GlitchTip/Sentry. The product needs admin-card routing, tenant visibility, and remediation governance more than symbolication infrastructure; keep `RawErrorCapturePort` so GlitchTip/Sentry can be added later for source maps.

**Biggest sad path/invariant.** Sad path: the pipeline becomes an amplifier, where noisy Gateway/pipeline errors create card storms and trigger unsafe remediation. Invariant: no card or action exists unless the event passed redaction, fingerprint quota, tenant/platform visibility, dead-letter fallback, and blast-radius/approval gates. A non-suppressible heartbeat card fires if ingestion stops.

**Parity + lean ops.** Harness OpenClaw signals through the ACL; keep Postgres as Opzava's incident/card SoT. Docs read: `cli/logs.md`, `automation/tasks.md`, `cli/tasks.md`, `plugins/workboard.md`, `cli/health.md`, `gateway/prometheus.md`, `gateway/protocol.md`, `plan/grilling-decisions.md`.
