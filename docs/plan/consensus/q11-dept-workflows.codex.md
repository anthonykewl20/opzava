# Q11 Department Workflows

**Decision.** Build one Opzava Workflow bounded context for Marketing, Finance, Support, and CRM. `Workflow`/`Playbook` is the definition aggregate and system of truth: tenant, department, autonomy tier, policy, `Trigger`, `Schedule`, steps, `ApprovalPolicy`, budget, concurrency, and projection keys. OpenClaw mechanisms are provisioned artifacts, not domain truth. Standing orders render into each `AgentEmployee` `AGENTS.md` for permanent authority; cron schedules one-shot/recurring triggers; managed Task Flow handles durable multi-step runs, waits, branching, resume, and cancel. Every cron/Task Flow execution creates OpenClaw task-ledger state. Provisioning is admin-context only (`operator.admin`); runtime commands use the locked broker token (`operator.write` + `operator.approvals`). Per Q4 hybrid CQRS, Opzava projects cron runs, task states, Task Flow revisions, usage/cost, and approval events into `WorkflowRun`/`RunStep`; OpenClaw snapshots are truth and WS events are hints.

**Aggregate sketch.** `Campaign` owns objective, budget, segment refs, channels, and window. `ContentCalendar` owns slots. `ContentItem` is the content root: `Idea -> Draft -> InReview -> Approved -> Scheduled -> Published -> Archived`; the `ContentPipeline` process manager asks a Marketing AgentEmployee to draft, routes review in chat, gates approve/schedule/publish through `Approval`, then records channel refs. `Report` is a versioned artifact with period, sources, freshness, metrics, narrative, generatedByRun, and provenance.

**Approval.** Opzava `Approval` is source of truth for business approvals: marketing content, finance actions, CRM merges/exports, and send-on-behalf. It surfaces as a Q7 chat inbox and blocks broker commands until `Approved`. OpenClaw exec/plugin approvals remain Gateway runtime truth for low-level tool/plugin execution. The broker mirrors those prompts into `Approval` with `openclawApprovalRef`, writes human decisions through `operator.approvals`, and reconciles by polling/events; disagreement fails closed as `BlockedExternal`.

**Department instances.** Finance event-ops is the same engine with T1 defaults: ingest events, reconcile, draft payment/invoice/refund recommendations, require approval before external mutation. Support SLA is the same engine with T2 ordinary replies, SLA clocks/escalations, and T1 gates for refunds, account changes, PII export, or legal language. CRM reuses T1 for imports, merges, exports, contracts, and record mutations; Marketing uses T2 for approved-brand posting but publication still requires content approval.

**Reports.** Reports are scheduled or event-triggered runs: agent run -> ACL reads from channels, CRM, usage/cost, ledger, and campaign data -> structured `Report` artifact -> chat/card delivery. Reports store `asOf`, source cursors, and freshness SLA; stale inputs produce a visible stale report, not a fabricated fresh one.

**Biggest sad path + invariant.** Biggest sad path: runaway standing orders/cron fan-out burns quota, duplicates scheduled runs, floods approvals, then bypasses review under pressure. Invariant: a workflow cannot be published unless every mechanism has `costBudgetPerHour`, `maxConcurrentRuns`, idempotency key, approval policy, timeout, retry cap, failure destination, and freshness SLA. `RunLimiter` enforces tenant/employee ceilings; duplicate trigger keys collapse; approval backlogs escalate before SLA breach. No `ContentItem` may enter `Scheduled` or `Published` unless it references an `Approved` business approval and matching content hash.

**Parity + lean ops.** Opzava defines policy and read models; OpenClaw executes through native standing orders, cron, Task Flow, tasks, channels, and approvals. One engine, one approval model, one broker projection path, per-tenant Gateway, and no per-department infrastructure keep operations VPS-cheap while leaving scale exits in ports.
