# Admin Control Center foundation decisions

Status: **Locked foundation — approved through the 2026-07-16 Admin grilling session**

This is the canonical decision ledger for the Admin Control Center information architecture, shared
Admin shell, and Overview composition. It records where an Opzava administrator finds a capability
and how cross-context readiness is projected. It does **not** move domain authority into the shell
or redefine the behavior owned by the referenced PRDs and ADRs.

This file describes target behavior. It does not claim that the Admin shell, Overview projections,
sidebar migration, setup pages, or leaf-page redesigns are implemented.

## 1. Scope, terms, and source-of-truth precedence

| ID      | Locked decision                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ACC-001 | **Admin Control Center** is the planning name for the Admin-only shell and page family. **Overview** is its visible landing page. The visible product and fork/runtime brand is **Opzava**. “Mainframe” and “OpenClaw” are not competing sidebar brands; OpenClaw may still appear where technical lineage or vendor documentation must be explicit.                                                               |
| ACC-002 | The Admin Control Center exists solely to develop, operate, secure, and configure the Opzava platform and its runtime. It is not a general business back office.                                                                                                                                                                                                                                                   |
| ACC-003 | CRM, Marketing, Finance, Contacts, Accounts, Deals, Tickets, campaigns, and other business-domain destinations do not appear in this Admin navigation. **Usage & Costs** is allowed only as platform-operational spend, quota, and capacity visibility; it is not a Finance workspace.                                                                                                                             |
| ACC-004 | The shell owns placement, navigation, cross-context projection, and interaction consistency. It never becomes the source of truth for a DevTicket, runner lease, Gateway state, Incident, credential, skill installation, approval, or audit event.                                                                                                                                                                |
| ACC-005 | The semantic sources of truth take precedence over this ledger: PRD-019 and ADR-017 for Dev Board and runner execution; PRD-013 for connections, providers, tools, setup, and MCP; PRD-012 and PRD-018 for observability and remediation; PRD-006 and PRD-007 for agents/runs and knowledge/skills; and PRD-001 for identity/profile security. | ACC-006 | An approved current PRD/ADR amendment outranks this ledger on underlying behavior. | ACC-007 | **Readiness** means whether a platform capability can safely perform its intended operation now, supported by freshness and evidence. **Attention** means a human decision or action is required. | ACC-008 | The existing **Ask Admin Opzava** design and behavior remain governed by its own approved issue, PRD-005, and applicable PRD-018/PRD-019 bounded actions. ## 3. Overview and topbar

| ID      | Locked decision                                                                                                                                                                                                                                                                                                                          |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ACC-021 | **Variant A — Priority Command Center** is the canonical Admin Overview reading flow. Its fixed section order is: **Needs Your Attention → Active Delivery → Development Readiness → Recent Activity**.                                                                                                                                  |
| ACC-022 | Needs Your Attention is the first section and contains only actionable items: approvals, blocked work, unhealthy integrations requiring intervention, disconnected execution, Review bottlenecks, security stops, or similarly bounded decisions. Every item states why it needs the human and offers a safe next action or destination. |
| ACC-023 | Active Delivery summarizes the currently active Sprint and ordinary Board work without becoming another board. It may show goal, progress, assignments, runner/tool identities, lane/WIP state, and links into the owning DevTickets or run views.                                                                                       |
| ACC-024 | Development Readiness projects the safe-to-operate status of GitHub, runners, the local Docker Review environment, Gateway, Slack Personal Assistant, Reviewer, and other necessary development capabilities. Each projection includes freshness/evidence and a route to its owner.                                                      |
| ACC-025 | Recent Activity is an attributable, time-ordered projection of meaningful platform changes and decisions. It is not a raw token stream, tool-call dump, mutable worklog, or replacement for the owning audit/execution view.                                                                                                             |
| ACC-026 | Admin Overview is distinct from Dev Board Summary. Overview answers “What needs me, what is moving, and is the development platform ready?” Dev Board Summary answers “What is the state of governed development work and its Goal?” Neither embeds a second copy of the other aggregate.                                                |
| ACC-027 | The shared topbar contains, in order appropriate to the viewport: sidebar trigger, global search, readiness health, adjacent attention/notifications, theme control, and profile. Search covers permitted Admin destinations and records without exposing restricted data.                                                               |
| ACC-028 | The health control reports aggregate readiness as Healthy, Degraded, Unhealthy, or Unknown with freshness. **Unknown is never rendered as healthy.** Selecting health opens or routes to evidence in Health/its owning setup page.                                                                                                       |
| ACC-029 | The adjacent attention control is a human-action feed, not a duplicate health indicator. Its accessible name communicates the actionable count; an empty feed has a clear zero/clear state rather than a misleading alert.                                                                                                               |
| ACC-030 | The profile menu shows the signed-in identity, role/account context, an Appearance shortcut/current preference, and Sign out. Security-sensitive profile and session management routes to the PRD-001-owned surface rather than being implemented in the menu.                                                                           |
| ACC-031 | The direct topbar theme control and profile Appearance entry edit the same preference. They must not drift into two theme states.                                                                                                                                                                                                        |
| ACC-032 | Overview cards expose deep links and bounded actions, not hidden mutations. Any approval, remediation, start, reconnect, or configuration action still invokes the owning application command and policy gate.                                                                                                                           |

## 4. States, themes, responsive behavior, and accessibility

| ID      | Locked decision                                                                                                                                                                                                                                                                              |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ACC-033 | The shared shell supports **Light, Dark, and System** appearance. System follows the operating-system preference until the Admin explicitly chooses Light or Dark. Theme and compact-sidebar preferences persist per device without overriding server-owned authorization or workflow state. |
| ACC-034 | Desktop supports expanded and icon-compact sidebar modes. On small screens the sidebar becomes a modal Sheet with an explicit trigger, backdrop/close behavior, focus trap, focus restoration, and background content made inert while open.                                                 |
| ACC-035 | The shell and Overview must work without horizontal page overflow at 320 px and at the supported tablet/desktop breakpoints. Touch targets are at least 44 by 44 CSS pixels where touch interaction is expected.                                                                             |
| ACC-036 | Every icon-only control and compact destination has an accessible name. The current page uses semantic current-state markup; disclosures expose expanded state and controlled region; headings preserve the top-to-bottom reading hierarchy.                                                 |
| ACC-037 | All pointer actions have keyboard equivalents. Focus remains visible in both themes, menus follow expected arrow/Escape/Home/End behavior, the mobile Sheet does not leak focus, and reduced-motion preferences are honored.                                                                 |
| ACC-038 | Loading preserves the stable shell and section identity while showing bounded skeleton/progress states. It must not briefly show stale facts as current or collapse the page into an unexplained blank.                                                                                      |
| ACC-039 | Clear/healthy state copy is internally coherent: it contains no stale degraded label, replay-lag warning, pending approval, or contradictory attention badge. Empty sections explain that no human action is required.                                                                       |
| ACC-040 | Errors are scoped to the failed projection with last-confirmed time, a safe retry or owning destination, and unaffected sections still usable. A partial fetch failure does not turn the entire platform into Unknown unless the aggregate truly cannot be computed.                         |
| ACC-041 | Degraded, stale, disconnected, and unhealthy states state the affected capability, last-confirmed evidence, practical effect, and whether human action is required. Color never carries the meaning alone.                                                                                   |
| ACC-042 | Unknown means evidence is missing or unverifiable and fails closed wherever an owner contract requires verified health. The UI does not invent reassuring fixture data or infer readiness from absence of errors.                                                                            |
| ACC-043 | Live announcements are reserved for meaningful async results and action outcomes. Background refreshes do not repeatedly steal focus or flood screen-reader announcements.                                                                                                                   |

## 6. Skills, MCP, and workflow boundaries

| ID      | Locked decision                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

It is deployed to the Lead Orchestrator and enrolled local harnesses only through version, compatibility, approval, and policy controls owned by PRD-007/PRD-013.                                                                                              |
| ACC-045 | Engineering Skills is not limited to four named skills. It may include the agreed engineering suite such as grilling/grill-with-docs, wayfinder, domain-modeling, research, prototype, to-spec, to-tickets/to-issues, implement, improve-codebase-architecture, code-review, QA, triage, and related governed skills. Catalog membership and canonical names are versioned rather than inferred from an illustration. |
| ACC-046 | Tracking an upstream fork means Opzava can detect and assess upstream changes. It does not mean a remote update silently replaces an approved skill in an active workflow or enrolled harness. Activation and rollout remain governed provisioning behavior.                                                                                                                                                          |
| ACC-047 | **Runtime Skills** are OpenClaw-native runtime skills. They remain a separate catalog and lifecycle from Engineering Skills even when one agent may be allowed to use both.                                                                                                                                                                                                                                           |
| ACC-048 | The **Ask Admin skill subset** is the separately governed subset allowed to the assistant under its role and tool policy. Pinning Ask Admin in the shell does not grant it the full Engineering Skills or Runtime Skills catalog.                                                                                                                                                                                     |
| ACC-049 | **MCP Servers** are configured MCP endpoints/transports and their exposed tools. They are not a skill type. An MCP tool may be made available to the orchestrator and to an enrolled local Codex/Claude harness only when the same identity, tenant, client, policy, and secret-reference checks allow it.                                                                                                            |
| ACC-050 | MCP configuration never gives a local tool a Gateway operator/admin token or makes the browser a direct Gateway client. Effective tools are deny-wins projections of the underlying policy.                                                                                                                                                                                                                           |
| ACC-051 | The Engineering Skills page may display source/provenance, canonical name, approved version, upstream availability, rollout target, compatibility, verification, policy, and drift. It does not own the semantics of research, prototyping, planning, implementation, deepening, review, or QA.                                                                                                                       |
| ACC-052 | The agreed engineering flow may use research and prototyping when an idea, wayfinder investigation, or vague contract needs evidence; implementation work includes the governed deepening/code-review stages defined by its Dev Board workflow. The Admin surface configures the available skills but does not run an alternate workflow state machine.                                                               |

| ACC-063 | Environments owns setup and readiness for the one shared local Docker Review stack, expected services/health checks, reset policy, fixtures, bounded preview/tunnel, evidence capture, and Reviewer compatibility. | ACC-066 | Runner disconnect, stale receipts, reconcile, Docker unavailability, and Review-stack contention render from last-confirmed evidence. The Overview does not claim continued execution or invent automatic cloud failover.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ACC-067 | Staging and production release readiness are separate from the local Docker Review environment and from DevTicket Done. This Admin foundation does not add release controls to Environments.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
